1. Problem 1: Hidden Markov Models

The main challenge was converting continuous log features into discrete observations for the HMM. Failed logins, bytes sent, and DNS queries were separately binned and combined using a mixed-radix encoding:

    o = 12*f_login + 3*f_bytes + f_dns

This kept the observation space compact (max symbol = 47) while preserving useful patterns. Very small bins made the emission matrix sparse; large bins destroyed signal.

I used 2 hidden states for normal vs suspicious behaviour. The provided Baum-Welch was a placeholder, so I implemented full EM with scaled forward-backward passes. Scaling at each timestep prevents underflow:

    alpha_t(i) = [ sum_j alpha_{t-1}(j) * a_{ji} ] * b_i(o_t) / c_t

Re-estimation equations:

    pi_i = gamma_1(i),  a_{ij} = sum_t xi_t(i,j) / sum_t gamma_t(i),  b_i(k) = sum_{t: o_t=k} gamma_t(i) / sum_t gamma_t(i)

The detect_intrusion function uses log-likelihood log P(O|lambda) as the anomaly score — lower values indicate more anomalous sequences. Model comparison selects the model with higher likelihood for the same sequence, which is the standard probabilistic model selection criterion.


2. Problem 2: Search

The 8-puzzle showed how heuristic quality directly controls A* performance. With h(n) = 0, A* degenerates to Dijkstra and expands far too many nodes. The goal was an admissible heuristic as tight as possible.

Manhattan distance is the standard admissible baseline:

    h_man(n) = sum_i ( |x_i - x_i*| + |y_i - y_i*| )

It is admissible since each tile needs at least that many moves ignoring others. However it underestimates whenever tiles block each other.

Linear Conflict adds a correction. If two tiles t_j, t_k are both in their goal row r but reversed (goal_col(t_j) > goal_col(t_k) yet col(t_j) < col(t_k)), at least 2 extra moves are needed. The same applies to columns. The combined heuristic is:

    h(n) = h_man(n) + 2 * LC(n)

This remains admissible since LC lower-bounds the extra moves required. On hard puzzles it expanded only 56 nodes vs thousands with h=0, while still guaranteeing the optimal solution via A* with f(n) = g(n) + h(n).


3. Problem 3: Reinforcement Learning

The key insight was that feature design, reward shaping, and epsilon scheduling together determine Q-learning quality. The template returned zero everywhere, giving the agent no signal.

I expanded the feature vector from 3 to 14 features including immediate wins, blocks, fork creation (2+ simultaneous threats), threat counts before/after, open lines, and positional control. The linear Q-function approximator computes:

    Q(s, a) = w^T * phi(s, a)

and updates weights via:

    w <- w + alpha * [ r + gamma * max_{a'} Q(s', a') - Q(s, a) ] * phi(s, a)

The reward function used terminal signals R = +1 (win), -1 (loss), -0.05 (draw), plus small shaping terms for creating threats (+0.05) and blocking opponent threats (+0.03). Epsilon followed exponential decay:

    epsilon_t = max(epsilon_min, epsilon_0 * decay^t)

with epsilon_0 = 0.9, decay = 0.995, epsilon_min = 0.05. After 500 episodes the agent achieved ~77% win rate against a random opponent, confirming that careful feature and reward design greatly improves RL performance.
